# ADR-001：AECP 数据库与模块基线

- 状态：Accepted
- 决策日期：2026-08-25
- 适用范围：Task 00 至一期 MVP 发布前
- 评审方式：产品范围、技术基线、试点数据三方记录

## 1. 背景

当前仓库是 Java 17、Spring Boot 3.4.4、Maven Wrapper 3.9.9 的后端工程骨架。docker-compose.yml 已提供 MySQL 8.4 和 Redis 7.4，.env.example 也已使用 MySQL JDBC URL。技术实现方案同时提出 PostgreSQL 15、S3/MinIO、RabbitMQ 和 WebSocket，因此需要在开始领域迁移和业务模块开发前冻结一套可运行基线。

本 ADR 只冻结工程选择和约束，不提前实现会议、任务、文件、部件或 STEP 业务。

## 2. 决策摘要

| 决策项 | 本期基线 | 评审结论 |
|---|---|---|
| 数据库 | MySQL 8.4 | 沿用当前仓库和已验证 Compose；PostgreSQL 15 作为未来迁移备选，不作为 Task 00 后的默认运行时 |
| 对象存储 | S3 兼容抽象，开发/测试/试点默认 MinIO | 应用只依赖对象存储接口；生产可替换为受控 S3 服务 |
| 异步队列 | RabbitMQ + Outbox | 事件先在同一数据库事务写入 Outbox，再投递 RabbitMQ；消息必须可重试、可去重、可进死信队列 |
| 认证 | 本地账号密码 + bcrypt；项目级 RBAC 和隔离 | 连续失败 5 次锁定 30 分钟；SSO 不进入一期；安全等级较高的试点可再打开 2FA 配置 |
| 试点项目负责人 | 脱敏演示负责人账号 demo-pilot-pm，职责为 AECP 试点项目经理 | 该账号是可复现演示数据，不冒充真实人员；Task 31 前必须由试点组织替换为实名责任人 |

## 3. 数据库取舍：MySQL 8.4 与 PostgreSQL 15

### 3.1 选择 MySQL 8.4

Task 00 至一期 MVP 默认使用 MySQL 8.4，原因如下：

1. 当前 Compose、环境变量和启动检查已经以 MySQL 8.4 为准，继续沿用不会引入第二套本地启动方式。
2. 当前目标是先完成会议、任务、文件、部件的可追溯主链路；这些模型主要使用关系表、外键、唯一约束和索引，暂不需要 PostgreSQL 专属能力。
3. 切换到 PostgreSQL 会同时影响 JDBC 驱动、连接池参数、迁移 SQL、JSON 查询、树查询、全文检索和本地数据卷，超出 Task 00 的冻结范围。

PostgreSQL 15 保留为可逆备选。只有在以下条件之一成立时才重新评审：中文全文检索被证明是 P0 阻塞；模型参数查询需要 PostgreSQL 专属 JSONB/GIN 能力；或试点数据量和查询基准表明 MySQL 约束无法达到 Task 29 的目标。重新评审必须附带迁移 PoC、基准数据、回滚方案和双数据库契约测试。

### 3.2 MySQL 实现约束

#### JSON

- 使用 MySQL JSON 列保存版本化的参数、导入元数据和批注扩展字段。
- JSON 内容由应用层按 schema_version 校验；业务上需要筛选的稳定字段使用普通列或生成列加索引。
- 不使用 PostgreSQL JSONB、->>、GIN 索引或数组类型作为业务契约，避免未来迁移时出现不可翻译 SQL。
- JSON 不是权限边界；组织、项目、部件负责人和文件权限必须使用关系表表达。

#### 树查询

- 部件树使用 project_id + parent_id + sort_order + depth 的邻接表模型，初始最大深度为 5。
- 子树和祖先查询使用 MySQL 8 的递归 CTE；所有查询必须先限定 project_id，并使用 project_id, parent_id, sort_order 索引。
- Task 04 先保证父子关系、项目隔离、环检测和深度上限；不在初始基线引入 ltree 或闭包表。
- 若 Task 29 的真实基准显示递归查询不足，再通过独立迁移增加闭包表或路径列，不改变外部 API。

#### 全文检索

- MySQL 默认分词器对中文短语和专业缩写的效果不作为一期承诺。
- MVP 先使用结构化过滤、精确匹配和受限数据集上的 LIKE/前缀查询，配合项目、部件、文件类型和时间索引。
- 不在未验证中文分词效果前把 MATCH ... AGAINST 写入业务契约；如需要全文能力，必须在固定 MySQL 8.4 镜像上验证 ngram 方案，或在 P1 引入独立搜索服务。
- 搜索质量、延迟和结果完整性由 Task 29 的真实数据基准决定，不能用静态 SQL 检查代替。

## 4. 模块和中间件边界

| 边界 | Task 00 冻结内容 | 后续实现任务 |
|---|---|---|
| 关系数据 | 业务数据永久保存；审计日志保留 180 天；软删除和项目隔离 | Task 04、Task 07 |
| 对象存储 | 文件二进制不进入数据库；保存对象 key、版本、大小、校验和、关联元数据 | Task 09、Task 10 |
| 消息投递 | Outbox 与业务写入同事务；消费者按事件 ID 幂等；失败重试并进入 DLQ | Task 12、Task 14 |
| 认证授权 | 账号、组织、项目成员、系统/项目角色分层；所有业务查询带项目边界 | Task 05、Task 06、Task 27 |
| STEP | 文件元数据和模型版本进入当前域；浏览器解析、性能和兼容性单独验收 | Task 19、Task 20 |
| 前端 | 当前 Spring Boot 欢迎页保留为后端 fallback；React 壳在后续 Task 01 建立 | Task 01 |

Task 02 才把 RabbitMQ 和 MinIO 加入本地 Compose；在此之前，后端骨架可以仅依赖当前已验证的 MySQL 和 Redis 启动。该安排是实施顺序，不是对最终中间件选型的否定。

## 5. 试点责任与演示账号

- 试点项目负责人：demo-pilot-pm（脱敏演示账号，角色为试点项目经理）。
- 业务验收责任：试点项目经理负责会议、任务、文件和部件主链路确认。
- 技术验收责任：AECP 技术负责人负责环境、迁移、权限、性能和回滚证据。
- 数据责任：双方组织管理员负责确认组织、成员、部件负责人和样本脱敏结果。
- 实名负责人是外部依赖，不在仓库中虚构；Task 31 前若未替换，禁止把演示结果写成真实试点结论。

## 6. 评审记录

| 评审项 | 决议 | 状态 | 影响/未决项 |
|---|---|---|---|
| 数据库基线 | MySQL 8.4；PostgreSQL 15 保留为有证据才触发的备选 | 已决 | Task 04 迁移必须遵守本 ADR 的 JSON、树和全文约束 |
| 对象存储 | S3 兼容接口，开发/测试/试点使用 MinIO | 已决 | Task 02 增加服务；真实生产桶、备份和密钥由发布环境提供 |
| 队列 | RabbitMQ，Outbox、重试、幂等、DLQ 为契约 | 已决 | Task 12 完成实现；Task 02 负责本地依赖 |
| 认证方式 | 本地账号密码、bcrypt、失败锁定和项目级 RBAC | 已决 | SSO 为排除项；2FA 是否打开由试点安全等级决定 |
| 试点项目负责人 | demo-pilot-pm 作为可复现演示负责人；实名负责人由试点组织指定 | 已决（演示）/待实名（真实试点） | 不阻塞本地骨架和契约开发；阻塞真实 UAT 结论 |

评审结论：五项基线已冻结。未决的实名负责人、真实对象存储、RabbitMQ/MinIO 环境凭据和 STEP 二进制样本属于外部环境输入，不阻塞 Task 01、Task 04 之前的本地工程工作；在对应任务的验收前必须补齐。

## 7. 影响、回滚和复审条件

- 正面影响：本地启动路径保持单一，Task 04 可以直接建立 MySQL 迁移，Task 09/12 可以围绕稳定接口接入 MinIO/RabbitMQ。
- 主要风险：中文全文检索、深层部件树和超大 STEP 文件可能暴露 MySQL 或浏览器性能边界。
- 回滚策略：在出现性能或能力阻塞时，保留关系模型和 API 契约，通过 expand-contract 迁移增加索引、路径列或搜索适配器；不得直接删除现有列或替换现有数据卷。
- 复审触发器：Task 19/29 的真实 STEP 与查询基准、Task 27 的安全验证、Task 30 的恢复演练任一不达标时，由产品和技术负责人重新评审本 ADR。
